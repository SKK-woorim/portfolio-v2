# 챗봇 호출 기록 구현·검증 계획

## 기록 범위

실시간 RAG 요청에 이미 부여되는 요청 ID를 사용한다. 질문 본문이나 세션 식별자를 수집하지 않고 실제 GPT, Gemini, 로컬 모델 호출을 연결한다. 키 조회 실패를 진단할 수 있도록 하되, 키가 없는 제공자와 검색·캐시 적중은 모델 호출 횟수에서 제외한다.

## 작업 순서

1. 서버 전용 쓰기·조회 함수와 메타데이터 저장 구조를 정의한다. 30일 보관 후 자동 삭제한다.
2. 원격 생성 및 로컬 스트림 경로에서 실제 시도와 결과를 수집한다. 기록 저장이 느리거나 실패하더라도 답변과 다음 모델로의 전환은 계속 진행한다.
3. 관리자 챗봇 화면에 호출 기록을 연결한다. 요청별로 시도를 묶고, 세부 내용에서 순서·모델·결과·소요 시간·HTTP 상태·보고된 토큰 수를 확인할 수 있게 한다.
4. 동일 요청에 대한 반복 쓰기, 권한 제한, 로그 필드, 저장 실패 시 동작, 관리자 조회와 페이지 이동을 검증한다.

## 검증 시나리오

| 상황 | 기대 결과 |
| --- | --- |
| GPT 성공 | GPT 시도 한 건 |
| GPT 시간 초과 후 Gemini 성공 | 같은 요청에 두 시도를 순서대로 표시 |
| 키가 없고 로컬 성공 | 로컬 호출만 집계 |
| 키 저장소 조회 실패 후 로컬 성공 | 키 조회 실패 원인 확인 가능 |
| 저장 지연 또는 오류 | 답변과 모델 전환 정상 |
| 비관리자 | 호출 기록 접근 차단 |
| 30일 경과 | 조회에서 제외되고 예약된 정리 작업으로 삭제 |
