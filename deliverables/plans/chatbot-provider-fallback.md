# 챗봇 API 우선 호출 구현 계획

## 목적과 범위

관리자가 등록한 API 키로 실시간 포트폴리오 챗봇의 답변을 생성한다. GPT(`gpt-6-luna`)를 우선 사용하고 Gemini(`gemini-3.8-flash`)와 기존 로컬 모델을 차례로 시도한다. 구현과 검증에는 모의 키와 모의 응답을 사용한다.

## 구현 순서

1. 관리자 페이지에 API 키 탭을 추가한다. 관리자 권한을 서버에서 확인한 후 제공자별로 키를 등록·교체·삭제할 수 있게 한다. 관리 화면에는 각 키의 등록 여부만 제공한다.
2. RAG API의 검색 및 프롬프트 조립 이후에 답변 생성 경로를 연결한다. 질문, 대화 기록, 검색 근거, 인용 지침을 기존 메시지에서 가져온다. 검색 결과가 없는 질문에는 기존 안내를 반환한다.
3. 매 요청마다 설정된 제공자를 우선순위대로 시도한다. 원격 호출에 시간 제한을 두고 인증 오류, 사용량 제한, 빈 응답, 연결 실패가 발생하면 다음 제공자로 넘어간다. 실패한 답변 조각이나 제공자 오류가 채팅에 노출되지 않게 한다.
4. 관리자 화면과 RAG 서비스가 같은 키 설정을 사용하도록 연결한다. 저장소 변경의 적용 순서와 운영 전제 조건을 확인한다.

## 인수 기준

| 조건 | 기대 결과 |
| --- | --- |
| 두 키가 모두 있고 GPT 성공 | GPT 답변 한 건만 표시 |
| GPT 실패, Gemini 성공 | 동일한 근거로 생성된 Gemini 답변 표시 |
| Gemini 키만 등록 | GPT 호출을 건너뛰고 Gemini 사용 |
| 두 API가 모두 실패하거나 두 키가 없음 | 기존 로컬 모델로 생성 |
| 키 교체·삭제 | 후속 질문에 새 설정 반영 |
| 관리 권한 없음 | 키 조회·변경 차단 |
| 모든 생성 경로가 실패 | 방문자에게 기존 일반 오류 안내 |

## 검증과 적용

GPT-6.2 Sol 에이전트가 관리자 기능과 생성 경로를 구현한다. 주 에이전트는 저장 권한, 키 노출 여부, 호출 순서 및 기존 RAG 응답 계약을 검토하고 관련 테스트를 실행한다. 운영 DB 변경과 실키를 이용한 유료 호출은 배포 단계에서 진행한다.

## 운영 적용 순서

1. Supabase 프로젝트에 `supabase/migrations/20261118011930_ai_provider_keys.sql`을 적용한다. 이 마이그레이션이 Vault 저장소를 사용하는 키 관리 함수를 추가한다.
2. 같은 Supabase 프로젝트를 바라보는 RAG API와 웹 앱을 배포한다. 두 서비스 모두 서버 전용 서비스 역할 키로 키 관리 함수에 접근한다.
3. 관리자 메뉴의 **API 키**에서 사용할 제공자의 키를 저장한다. 실시간 질문으로 확인한다. 현재 콘텐츠와 일치하는 저장 답변이 있는 질문은 기존 캐시가 먼저 처리한다.

## 검증 결과

웹 테스트 297개, RAG 전체 테스트, 타입 검사, ESLint, 마이그레이션 계약 검사, Next.js 프로덕션 빌드를 통과했다. 최종 모델 ID도 모의 HTTP 요청에서 확인했다. 운영 Vault 조회와 실제 제공자 인증·응답은 마이그레이션 배포 및 실키 등록 이후 확인한다.
