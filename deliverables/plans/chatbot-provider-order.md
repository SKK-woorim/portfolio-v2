# 챗봇 모델 호출 순서 설정 계획

관리자 → API 키에서 GPT, Gemini, 로컬 AI를 원하는 순서로 배치하고 저장한다. 초기 순서는 GPT → Gemini → 로컬 AI다. 순서 변경은 다음 실시간 요청부터 반영한다.

## 구현

1. DB에 세 모델이 한 번씩 등장하는 순서를 저장한다. 관리자 화면은 키 등록 정보만, RAG 서버는 실제 호출에 필요한 설정을 읽는다.
2. RAG 서버는 요청 시작 시 읽은 순서로 사용 가능한 모델을 시도하고 첫 성공에서 멈춘다. 키 없는 모델은 건너뛴다.
3. 로컬 모델 뒤에 다른 후보가 있으면 로컬 답변이 완성된 뒤 전송해 실패한 부분 응답과 다음 모델의 답변이 섞이는 것을 막는다.

## 검증

- 여섯 순서가 저장·조회되고, 중복·누락된 모델이나 비인가 쓰기는 거부된다.
- 로컬 우선 성공 시 API 호출이 없고, 로컬 실패·대기열 포화 시 다음 후보로 넘어간다.
- 호출 로그의 시도 순서가 실제 요청과 일치한다. 캐시 적중은 기존 캐시 경로를 사용한다.
- 설정 조회 실패, 키 미등록, 응답 시간 초과 및 클라이언트 취소 상황을 점검한다.
