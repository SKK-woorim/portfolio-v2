# CMS 작성·미디어 개선 기획서

- 관련 항목: `CMS-01`~`CMS-06`, `CMS-03`은 P0
- 주요 사용자: 단일 관리자
- 목표: 게시글과 포트폴리오 본문 작성, 이미지 삽입, 발행과 복구를 관리자 화면 안에서 끝낸다.

## 1. 배경과 문제

현재 본문 포맷은 Markdown이며 `MarkdownEditor`는 작성·미리보기만 제공한다. 미디어 업로드는 별도 페이지에 있고, 미디어 카드에는 URL 복사 기능이 없다. 본문에 이미지를 넣으려면 관리자가 공개 URL을 별도로 확보하고 `![대체 텍스트](URL)`을 직접 입력해야 한다.

대표 이미지는 DB 관계로 추적되지만 Markdown 본문의 이미지는 URL 문자열로만 남는다. 따라서 미디어 삭제 시 대표 이미지 사용 여부만 확인되고, 발행 본문에서 사용 중인 파일은 삭제될 수 있다. 긴 글 작성 중 이탈 보호, 자동 복구, 실제 공개 레이아웃 미리보기와 수정 이력도 없다.

## 2. 목표와 제외 범위

### 목표

- 편집기에서 기존 미디어를 찾거나 새 파일을 업로드하고 즉시 본문에 삽입한다.
- 이미지마다 대체 텍스트를 작성하게 하고, 사용 중인 이미지는 삭제할 수 없게 한다.
- 저장·이탈·발행 상태를 명확히 보여 장문 작성의 손실과 발행 실수를 줄인다.
- 이전 버전을 확인하고 선택적으로 복원할 수 있는 확장 경로를 마련한다.

### 제외 범위

- 1차 단계에서 본문 저장 포맷을 Tiptap JSON으로 다시 변경하지 않는다.
- 동영상 편집, 이미지 크롭 스튜디오, 협업 동시 편집은 포함하지 않는다.
- 외부 URL 이미지는 표시할 수 있지만 미디어 라이브러리 자산처럼 수명주기를 보장하지 않는다.

## 3. 핵심 사용자 흐름

### 3.1 본문 이미지 삽입

1. 관리자가 본문 편집기 도구 모음의 `이미지 넣기`를 선택한다.
2. 미디어 선택 창에서 alt, 파일명, 업로드 날짜로 검색하거나 새 이미지를 업로드한다.
3. 새 이미지에는 대체 텍스트를 필수 입력한다. 장식 이미지인 경우에만 `장식용 이미지`를 명시적으로 선택해 빈 alt를 허용한다.
4. 선택한 이미지를 현재 커서 위치에 `![대체 텍스트](공개 URL)` 형식으로 삽입한다.
5. 미리보기에서 실제 렌더링과 alt를 확인한다.
6. 저장 시 서버가 본문 속 내부 미디어 URL을 분석해 사용 관계를 갱신한다.

### 3.2 장문 작성과 복구

1. 입력이 바뀌면 `저장되지 않음` 상태를 표시한다.
2. 마지막 서버 저장과 별도로 브라우저에 복구 초안을 일정 간격으로 저장한다.
3. 저장 전 페이지를 닫거나 이동하면 이탈 경고를 표시한다.
4. 같은 콘텐츠를 다시 열었을 때 서버본보다 최신 로컬 초안이 있으면 비교 후 복원 또는 폐기하게 한다.
5. 서버 저장 성공 시 `방금 저장됨`과 저장 시각을 표시하고 해당 로컬 초안을 제거한다.

### 3.3 발행 전 확인

- `실제 페이지 미리보기`는 관리자 인증이 있어야 열리는 서명된 단기 URL을 사용한다.
- 발행 직전 제목, slug, 요약, 본문, 대표 이미지 alt, SEO 설명, 깨진 내부 이미지, 링크 형식을 검사한다.
- 경고는 발행 가능 경고와 발행 차단 오류를 구분한다.
- 기존 발행 글의 slug 변경 시 예전 경로의 처리 방법을 안내한다. 영구 리디렉션 기능이 준비되기 전에는 변경을 강하게 경고한다.

## 4. 화면 요구사항

### 4.1 Markdown 편집기

- 작성·미리보기 탭은 유지한다.
- 도구 모음에 제목, 굵게, 링크, 코드, 목록, 인용, 표, 이미지 삽입 버튼을 제공한다.
- 이미지 버튼은 modal 또는 dialog를 열고, 기존 자산 선택과 새 업로드를 한 흐름에 둔다.
- 선택된 이미지 썸네일, alt, 용량, 사용 횟수를 표시한다.
- 업로드·삽입 성공은 화면 읽기 프로그램이 인지할 수 있는 상태 메시지로 알린다.
- 텍스트 선택과 커서 위치를 유지해 Markdown 문법을 삽입한다.
- 붙여넣기와 drag-and-drop 업로드는 2차 범위로 두되 동일한 검증 경로를 재사용한다.

### 4.2 미디어 라이브러리

- 카드마다 `본문에 쓸 URL 복사`, `alt 수정`, `사용처 보기`, `삭제`를 제공한다.
- 파일명, alt, MIME, 크기, 업로드 시각, 사용 횟수를 표시한다.
- 사용처 패널에서 대표/본문 역할과 콘텐츠 제목, 편집 링크를 보여준다.
- 사용 중인 자산의 삭제 버튼은 비활성화하고 이유와 사용처를 제공한다.
- 미사용 자산만 모아 보는 필터를 제공하되 일괄 삭제는 1차 범위에서 제외한다.

### 4.3 작성 폼

- slug는 제목에서 제안하되 관리자가 확정할 수 있게 한다.
- 대표 이미지는 텍스트 select 대신 썸네일을 확인할 수 있는 선택기로 바꾼다.
- 저장 버튼 주변에 `저장되지 않음`, `저장 중`, `저장됨`, `저장 실패` 상태를 표시한다.
- 저장 실패 후에도 모든 입력값을 유지한다.
- 발행과 초안 저장은 시각적 우선순위를 구분하고 중복 제출을 막는다.

## 5. 데이터와 기술 설계

### 5.1 기준 포맷

`content_json = { type: "markdown", markdown: string }`을 계속 기준으로 사용한다. 현재 사용되지 않는 `RichTextEditor`는 바로 재활성화하지 않고, Markdown 편집기의 도구 모음과 미디어 선택 기능을 확장한다. 이 결정은 레거시 Tiptap 문서 변환과 공개 Markdown 렌더러의 현재 동작을 보존한다.

### 5.2 미디어 사용 관계

새 테이블 예시:

```text
media_usages
- media_id uuid
- owner_type post | portfolio | site_profile
- owner_id uuid 또는 profile 고정 식별자
- role cover | inline | gallery | avatar
- source_path text nullable
- created_at timestamptz
- primary key(media_id, owner_type, owner_id, role, source_path)
```

- 본문 저장 시 동일 트랜잭션에서 내부 Storage URL을 파싱하고 `media.public_url`과 대조한다.
- 해당 콘텐츠의 기존 `inline` 관계를 새 집합으로 교체한다.
- 외부 도메인 이미지는 관계를 만들지 않고 발행 체크리스트에서 외부 의존 경고를 표시한다.
- 대표·갤러리·아바타 관계도 장기적으로 이 테이블에서 통합 조회하되, 기존 FK를 바로 제거하지 않는다.
- 삭제 RPC는 관계가 한 건이라도 있으면 사용처 목록을 반환하고 삭제하지 않는다.

### 5.3 로컬 복구 초안

- 키: `content-type`, 콘텐츠 ID 또는 신규 임시 ID, 관리자 ID를 조합한다.
- 값: 폼 필드, 작성 시각, 서버 기준 `updated_at`을 저장한다.
- 비밀번호, 세션, 비밀 설정은 저장하지 않는다.
- 보존 기간은 7일, 성공 저장 또는 명시적 폐기 시 제거한다.
- 여러 탭 충돌 시 더 최신이라고 자동 덮어쓰지 말고 비교 선택을 제공한다.

### 5.4 수정 이력

2차 단계에 `content_revisions`를 추가한다.

```text
content_revisions
- id uuid
- owner_type post | portfolio
- owner_id uuid
- revision_number integer
- snapshot jsonb
- actor_id uuid
- reason text nullable
- created_at timestamptz
```

- 서버 저장 트랜잭션에서 변경 전 또는 변경 후 스냅샷을 일관된 정책으로 기록한다.
- 동일 내용의 연속 저장은 content hash로 중복 버전을 만들지 않는다.
- 복원은 과거 버전을 현재 초안으로 복사하며 과거 행 자체를 수정하지 않는다.

## 6. 서버 동작과 검증

- 업로드는 기존 인증·용량·MIME 검증에 더해 [보안·정합성 기획](./05-security-and-data-integrity-plan.md)의 파일 내용 검사를 적용한다.
- 본문 이미지 URL은 `https`와 사이트가 관리하는 Supabase Storage origin을 우선 허용한다.
- 외부 이미지를 허용할 경우 `http`는 발행 차단하고 `https`만 허용한다.
- 공개 렌더러는 이미지 alt, loading, decoding, 크기 정보를 안전하게 출력한다.
- 저장과 미디어 사용 관계 갱신은 [원자적 저장](./05-security-and-data-integrity-plan.md) RPC에 포함한다.

## 7. 접근성 요구사항

- 미디어 선택 dialog는 열릴 때 제목으로 포커스를 이동하고, 닫을 때 이미지 버튼으로 복귀한다.
- 썸네일만으로 선택 상태를 전달하지 않고 텍스트와 체크 상태를 함께 제공한다.
- 장식용 여부가 아니면 alt가 비어 있을 때 삽입과 발행을 차단한다.
- 작성·미리보기 탭은 적절한 tab 역할과 키보드 전환을 지원한다.
- 오류는 입력과 연결하고 최초 오류로 포커스를 이동한다.

## 8. 단계별 구현

- 미디어 URL 복사와 사용처 조회
- 편집기 미디어 선택·업로드·삽입
- 본문 내부 미디어 관계 동기화

- 공개 레이아웃 미리보기
- 발행 체크리스트와 slug 사전 검증

## 9. 테스트 계획

- 커서 앞·뒤·선택 영역에 이미지 Markdown이 정확히 삽입된다.
- 업로드 실패, 잘못된 파일, 중복 클릭에도 본문이 유지된다.
- 내부 이미지가 포함된 글을 저장하면 사용 관계가 생성되고 제거하면 관계가 삭제된다.
- 대표 또는 본문에서 사용 중인 미디어 삭제가 차단되고 정확한 사용처를 반환한다.
- 외부 URL 이미지는 내부 사용 관계로 오인되지 않는다.
- 새 탭, 새 글, 기존 글, 저장 실패 각각에서 복구 초안이 섞이지 않는다.
- 키보드만으로 dialog 열기, 검색, 선택, 삽입, 닫기가 가능하다.
- 실제 공개 페이지 미리보기는 인증되지 않은 요청과 만료된 토큰을 거절한다.

## 10. 완료 기준

- 관리자는 다른 페이지에서 URL을 복사하지 않고도 본문 이미지를 업로드·삽입할 수 있다.
- 발행 중인 콘텐츠가 참조하는 내부 미디어는 삭제할 수 없다.
- 저장 실패나 실수로 페이지를 닫아도 최근 작성 내용을 복원할 수 있다.
- 발행 전 실제 공개 형태와 필수 메타데이터를 확인할 수 있다.
- 기존 Markdown 콘텐츠와 공개 URL이 변경 없이 렌더링된다.

## 11. 위험과 대응

- Markdown URL 파싱만으로 사용 관계가 누락될 수 있다. 공용 parser를 저장·렌더링·검증에서 재사용하고 테스트 fixture를 고정한다.
- 브라우저 로컬 초안이 서버 최신본을 덮을 수 있다. `updated_at` 비교 후 사용자 선택을 요구한다.
- 미디어 선택기에 전체 자산을 한 번에 로드하면 느려질 수 있다. 검색과 cursor 페이지네이션을 서버에 둔다.
- 수정 이력은 저장량을 늘린다. 보존 개수 또는 기간 정책과 수동 영구 보존 표시를 둔다.
