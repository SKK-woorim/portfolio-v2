# 접근성·테마 품질 개선 기획서

- 관련 항목: `A11Y-01`~`A11Y-04`
- 목표 수준: WCAG 2.2 AA를 기준으로 공개 핵심 여정을 키보드와 보조기술로 완료
- 적용 범위: 공개 사이트 우선, 이후 관리자 CMS

## 1. 배경과 문제

현재 사이트에는 focus ring, 모바일 메뉴의 접근성 이름과 펼침 상태, 이미지 alt fallback, reduced-motion CSS가 있다. 다크·라이트 테마는 `localStorage`에 저장되지만 첫 방문은 운영체제 설정과 관계없이 다크로 고정된다. 토글 버튼의 이름도 현재 상태와 다음 동작을 구분하지 않는다.

블로그 필터와 주요 내비게이션에는 현재 위치를 전달하는 상태가 부족하고, 본문으로 바로 이동하는 건너뛰기 링크가 없다. 챗봇은 dialog와 유사한 고정 패널이므로 열기·닫기·포커스·스크롤 처리까지 실제 키보드와 스크린리더 검증이 필요하다. 두 테마의 모든 상태 색을 자동·수동으로 반복 검수하는 체계도 없다.

## 2. 원칙

- 색, 위치, 애니메이션만으로 의미를 전달하지 않는다.
- 모든 핵심 기능은 마우스 없이 완료할 수 있어야 한다.
- 포커스를 예측 가능하게 이동하고, 닫힌 UI 뒤의 요소로 빠져나가지 않게 한다.
- 두 테마는 동일한 정보 위계와 기능을 제공한다.
- 자동 검사 통과를 완료로 간주하지 않고 키보드·스크린리더·확대 검수를 함께 수행한다.

## 3. 내비게이션과 문서 구조

### 요구사항

- `<body>` 첫 상호작용 요소로 `본문으로 건너뛰기` 링크를 제공한다.
- 공개 레이아웃의 `<main>`에 안정적인 ID와 하나의 주 랜드마크를 둔다.
- 데스크톱·모바일 메뉴에서 현재 경로에 `aria-current="page"`를 설정한다.
- 로고 링크, 주요 메뉴, 테마, 문의 CTA의 탭 순서는 시각 순서와 일치한다.
- 모바일 메뉴가 열리면 첫 메뉴로 포커스를 옮기거나, 버튼 다음에 자연스럽게 이어지는 구조를 유지한다. 닫을 때는 메뉴 버튼으로 복귀한다.
- 페이지마다 하나의 명확한 `h1`을 두고 제목 수준을 건너뛰지 않는다.
- 외부 링크는 새 창 여부를 아이콘만이 아니라 접근 가능한 이름 또는 보조 문구로 알린다.

## 4. 테마 정책

### 4.1 상태 모델

테마 상태를 `system | dark | light` 세 값으로 정의한다.

- 저장값이 없으면 `system`으로 간주하고 `prefers-color-scheme`을 따른다.
- 사용자가 토글하면 `dark` 또는 `light`를 명시적으로 저장한다.
- 설정 화면 또는 순환형 토글에서 `시스템 설정 사용`으로 돌아갈 수 있게 한다.
- 시스템 설정이 바뀌면 `system` 상태에서만 즉시 반영한다.

단순 토글을 유지할 경우 버튼 이름은 현재 상태 기준으로 `라이트 모드로 전환` 또는 `다크 모드로 전환`처럼 바뀌어야 한다. 세 상태 제어를 도입하면 radio group 또는 menu로 명확히 표현한다.

### 4.2 초기 렌더링

- React hydration 전에 올바른 테마를 적용해 깜빡임을 줄인다.
- 동시에 CSP의 inline script 완화 계획과 충돌하지 않도록 nonce/hash 또는 안전한 서버 렌더링 방식을 [보안 기획](./05-security-and-data-integrity-plan.md)과 함께 결정한다.
- JavaScript가 꺼져도 시스템 기본 테마와 본문 가독성이 유지되어야 한다.

### 4.3 토큰 검수

다음 조합을 다크·라이트 모두 검사한다.

- 캔버스/표면 위 제목·본문·보조문구
- 기본·hover·focus·disabled 버튼
- 링크와 링크 hover
- 태그, 상태 badge, 오류·성공·경고 메시지
- 코드 블록, 인용문, 표, 입력 placeholder와 border
- 챗봇 사용자·AI 말풍선과 출처 카드

## 5. 챗봇 접근성

### 패널 동작

- 트리거는 현재 상태에 따라 `챗봇 열기`/`챗봇 닫기` 이름과 expanded 상태를 제공한다.
- 패널을 dialog로 취급하고 접근 가능한 제목과 설명을 연결한다.
- 열면 제목 또는 첫 의미 있는 컨트롤로 포커스를 옮긴다.
- 데스크톱 modal 동작을 선택한 경우 포커스를 패널 안에 가두고 배경은 상호작용하지 못하게 한다.
- Escape로 닫고, 닫으면 원래 트리거로 포커스를 복귀한다.
- 메시지 생성 상태는 `aria-live="polite"`, 치명 오류는 `role="alert"`로 전달한다.
- 새 토큰마다 과도하게 읽지 않도록 스트리밍 중에는 묶어서 알리고 완료 시 전체 응답을 안내한다.
- 새 메시지로 자동 스크롤하더라도 사용자가 과거 메시지를 읽는 중이면 위치를 강제로 빼앗지 않는다.
- 모바일 키보드가 열린 상태에서 입력과 전송 버튼이 가려지지 않는다.

## 6. 콘텐츠와 미디어 접근성

- CMS 내부 이미지에는 의미 있는 alt를 기본으로 요구하고 장식 이미지에만 빈 alt를 허용한다.
- 링크 텍스트는 `여기`, `보기`보다 대상이 드러나게 작성한다.
- 표에는 header cell과 필요 시 caption을 제공하고 작은 화면에서는 가로 스크롤 영역임을 알린다.
- 코드 블록은 키보드로 전체 내용을 읽고 선택할 수 있어야 한다.
- 날짜와 기간은 화면 표시와 기계 판독 가능한 `datetime`을 함께 제공한다.
- 태그·카테고리 필터는 선택 상태와 결과 수를 보조기술에 전달한다.

## 7. 관리자 화면 확장

공개 경로 완료 후 같은 기준을 관리자에 적용한다.

- 모든 입력 오류를 label·description과 연결한다.
- 저장 결과를 live region으로 알리고 실패 시 입력을 유지한다.
- drag-and-drop 포트폴리오 정렬에 키보드 대체 조작과 현재 위치 안내를 제공한다.
- 데이터 표의 빈 제목 셀을 `작업`처럼 명시하고 행별 편집·상태 버튼 이름에 콘텐츠 제목을 포함한다.
- 삭제, 전체 재인덱싱 등 영향이 큰 작업은 접근 가능한 확인 dialog를 거친다.

## 8. 자동 검수와 수동 검수

### 자동 검수

- Playwright 핵심 여정에 axe 검사를 연결한다.
- dark/light 각각 홈, 목록, 상세, 연락처, 챗봇 열림 상태를 검사한다.
- critical/serious 위반 0건을 merge 기준으로 한다.
- ESLint의 JSX 접근성 규칙 도입 범위를 검토한다.

### 수동 검수표

- 키보드: Tab, Shift+Tab, Enter, Space, Escape, 화살표 키
- 화면 확대: 200% 텍스트 확대와 400% 브라우저 zoom에서 가로 양방향 스크롤 없이 핵심 작업 완료
- 화면 크기: 360×800, 768×1024, 1440×900
- 모션: reduced motion에서 필수 정보 손실 없음
- 색상: 두 테마와 고대비 환경에서 focus와 상태 식별
- 보조기술: Chromium 계열 화면 읽기 프로그램으로 메뉴, 필터, 챗봇, 작성 폼 smoke test

## 9. 단계별 구현

### 1차: 공개 기본 흐름

- 건너뛰기 링크, main ID, 현재 메뉴 상태
- 테마 버튼의 동적 이름과 시스템 기본값
- 필터 선택 상태
- 두 테마 대비 수정

### 2차: 복합 상호작용

- 챗봇 dialog 포커스·Escape·live region
- 모바일 메뉴 포커스 복귀
- Markdown 표·제목·외부 링크 개선

### 3차: 자동화와 관리자

- axe 기반 E2E 품질 게이트
- 관리자 폼, 표, 정렬, 확인 dialog
- 정기 수동 검수 기록 양식

## 10. 테스트 시나리오

- 첫 방문의 시스템 테마, 명시적 light/dark, 저장 차단 환경에서 예상 테마가 적용된다.
- 토글 이름이 현재 테마와 다음 동작에 맞고 새로고침 후 유지된다.
- 건너뛰기 링크로 header와 챗봇 버튼을 건너 main 첫 콘텐츠에 도달한다.
- 현재 페이지와 활성 필터가 화면 읽기 프로그램에 전달된다.
- 챗봇을 열고 질문·취소·재시도·닫기를 키보드만으로 완료한다.
- 패널을 닫으면 트리거로 포커스가 돌아오고 배경 스크롤 잠금이 해제된다.
- 200% 확대에서 문의, 게시글 검색, 관리자 저장을 완료한다.

## 11. 완료 기준

- 공개 핵심 경로와 챗봇의 자동 검사에서 critical/serious 위반이 없다.
- 키보드만으로 내비게이션, 필터, 상세 열람, 문의 이동, 챗봇 질문을 완료한다.
- 두 테마의 일반 텍스트와 상호작용 상태가 목표 대비를 충족한다.
- 첫 방문은 시스템 설정을 존중하고 사용자의 명시적 선택은 안정적으로 유지된다.
- 관리자 핵심 작성 흐름에서 오류와 저장 상태를 보조기술로 확인할 수 있다.
