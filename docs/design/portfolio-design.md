# Portfolio V2 디자인 기준

이 문서는 [VoltAgent awesome-design-md의 Coinbase DESIGN.md](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/coinbase/DESIGN.md)를 읽고, Portfolio V2 기획서에 맞게 재해석한 구현 기준이다. 원본의 브랜드·콘텐츠·상표는 사용하지 않는다.

## 방향

- OG 공유 카드와 연결되는 딥 네이비·전기 블루 기반의 기술 편집형 포트폴리오.
- 넉넉한 섹션 여백, 단정한 정보 위계, 하나의 강한 CTA만 두는 흐름.
- 공개 영역은 딥 네이비 캔버스와 한 단계 밝은 블루 표면을 중심으로 구성한다.
- 데이터 그리드, 연결선, 상태 점을 제한적으로 사용해 AI Agent·RAG·ETL 흐름을 암시한다.
- 표면은 얇은 푸른 테두리와 낮은 대비의 그림자만 사용하며 본문 가독성을 우선한다.

## 구현 규칙

- CTA는 44px 이상 높이의 알약형 버튼으로 만든다.
- 카드는 24px 반경, 내부 여백 24~32px, 얇은 테두리를 기본으로 한다.
- 제목은 Pretendard Variable 400~600 굵기와 약한 음수 자간을 사용한다. 과도한 굵은 제목을 피한다.
- 넓은 화면에서는 콘텐츠 폭을 1200px로 제한하고, 섹션 위아래 여백은 96px를 기본으로 한다.
- 768px 미만에서는 메뉴를 햄버거로 바꾸고, 카드 그리드는 한 열로 축소한다.
- 포트폴리오 히어로에는 OG 카드의 연결형 데이터 파이프라인과 같은 시각 언어를 사용하되, 강한 유리 효과나 과도한 광원은 피한다.

## 2026-09-24 시각 개선

09-24 시각 개선 목업(로컬 전용, 저장소에 포함하지 않음)을 검토해 채택한 규칙이다. 위의 토큰과 구현 규칙은 그대로 유지하고, 아래 내용을 더한다.

### 방향

- 정적인 카드 대신 "작동하는 도식"을 쓴다. 사이트가 말하는 역량인 "문서를 지식으로, 질문을 실행으로"를 화면이 직접 재생한다.
- 움직임은 히어로 콘솔, 히어로 배경, 프로젝트 썸네일에만 둔다. 본문, 글 목록, 상세 페이지는 조용하게 유지한다.
- 유리 효과(배경 흐림)는 헤더, 히어로 콘솔, 챗봇 패널처럼 떠 있는 표면에만 쓴다.
- 모든 움직임은 `prefers-reduced-motion`이면 완성 상태로 멈추고, 화면 밖에서는 그리지 않는다.

### 추가 토큰: 프로젝트 색

썸네일 도식과 카드 강조(스포트라이트 테두리, 사실 칩)에만 쓴다. 본문 색이나 CTA에는 쓰지 않는다.

| 역할 | 다크 | 라이트 | 사용 |
| --- | --- | --- | --- |
| Signal (기존 Primary) | `#75B6FF` | `#0C5FBD` | AI Agent & RAG |
| Water | `#4FD6E6` | `#068094` | 지하수 수위 예측 |
| Hive | `#F4B740` | `#B07000` | 꿀벌지키미, "자료 필요" 표시 |
| Clay | `#FF8C78` | `#CD4A32` | T2G |
| Danger | `#FF7070` | `#CD2D2D` | 탐지 경고, 챗봇 연결 오류 |
| OK | `#3BD58A` | `#16965A` | 챗봇 온라인, 평가 통과 |

### 타이포그래피

- 히어로·CTA 제목은 Pretendard 300 굵기에 핵심어만 620으로 강조하고, 자간은 `-.055em`으로 둔다.
- 라벨, 수치, 코드, 도식 글자는 Martian Mono(Google Fonts) 400·500을 쓴다. 한글은 Pretendard로 대체되도록 폰트 스택 뒤에 둔다.
- eyebrow 라벨은 한국어로 쓴다(N16).

### 홈 구성

1. 히어로: 헤드라인 "문서를 지식으로, 질문을 실행으로."와 순환하는 문서 형식 칩(HWP·PDF·HWPX), 수상·발표 이력 3줄, 오른쪽에 히어로 챗봇 콘솔을 둔다. 배경에서는 문서 입자가 콘솔로 흘러든다.
2. 기술 스택 띠: 한 줄로 흐르고, 커서를 올리면 멈춘다. 기술 태그는 여기에서만 반복한다.
3. 대표 프로젝트 벤토: 첫 항목을 크게 두고, 카드마다 프로젝트별 생성형 도식을 쓴다. 카드 정보 순서는 제목 → 결과·역할·수상 → 기간·태그다.
4. 일하는 방식: 정의 → 설계 → 검증 세 단계와 챗봇 평가 질문 50개(그룹별 막대)를 보여준다.
5. 최근 글: 카드 대신 목록 행으로 보여준다.
6. CTA: 이메일 주소를 선택 가능한 글자와 복사 버튼으로 보여준다.

### 챗봇 표시 규칙

- 히어로 콘솔이 곧 챗봇이다. 우측 하단 버튼은 기존 위치·디자인을 유지하고, 콘솔이 화면에 보이는 동안만 숨긴다.
- 히어로 콘솔은 고정 높이(데스크톱 704px, 모바일 640px)로 두고, 질문·근거·답변 영역만 안에서 스크롤한다. 답변이 길어져도 왼쪽 글자와 아래 섹션이 움직이지 않아야 한다. 답변이 넘치면 스트리밍을 따라 내려가되, 사용자가 직접 스크롤하면 따라가기를 멈춘다.
- 챗봇 상태에 따라 문구가 바뀌는 히어로 버튼은 모바일에서 세로로 쌓아, 문구 길이 때문에 높이가 달라지지 않게 한다.
- 진행 단계 칩, 6초 느린 응답 안내, 꺼짐·오류 상태는 로드맵 N25–N29를 따른다.
- 연출 시간 때문에 실제 답변이 늦어지면 안 된다. 근거 목록과 점수는 서버가 보낸 값으로만 채운다.

### 프로젝트 썸네일 도식

| 도식 | 예시 | 표현 |
| --- | --- | --- |
| 파이프라인 그래프 | AI Agent & RAG | 문서 → OCR → 청크 → 지식베이스 → Agent → SQL·DB 노드와 흐르는 신호 |
| 시계열 곡선 | 지하수 수위 예측 | 관측·예측 곡선, 테스트 구간, 주요 지표 문구 |
| 객체 탐지 | 꿀벌지키미 | 벌집 격자, 탐지 박스와 신뢰도 라벨, 경고 칩 |
| 3D 메쉬 | T2G | 예시 문장과 함께 아래에서 위로 생성되는 와이어프레임 |
| 기본 패턴 | 새 프로젝트 | slug로 정해지는 격자·노드 패턴 |

- 도식 속 곡선·장면은 연출용이다. 실제 수치처럼 보이는 값에는 "도식 예시"를 붙이고, 공개 콘텐츠에 있는 수치만 문구로 쓴다.
- 도식 종류와 문구는 CMS에서 고른다(N31). 커버 이미지가 있으면 이미지를 우선한다.
